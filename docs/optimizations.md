# 改进与取舍

## OPT-001：用可替换模型接口支持离线验证

- 原问题：若所有测试都调用模型 API，开发反馈受网络、费用和模型输出波动影响。
- 实现：Runner 依赖 `ModelClient` 协议；真实 SDK 适配器和脚本化模型提供同一事件接口。
- 作用机制：离线测试可以精确安排工具调用、错误和中断，稳定验证宿主逻辑；真实模型另做验收。
- 改善性质：可测试性与可维护性。不是模型能力提升。
- 代价：需要维护一个小型内部消息层；模拟测试无法覆盖模型是否会正确选择工具。
- 证据：对应多轮、顺序执行、工具错误反馈、响应中断等离线用例；验证结果见进度文档。
- 性能：未做吞吐或耗时对照测量，不报告提升百分比。

## OPT-002：完整接收并校验轮次后再执行工具

- 风险：截断响应可能携带看似可用的部分工具参数；一边接收一边执行可能造成不完整动作。
- 实现：先收完模型轮次，再检查结束原因、重复调用 ID 和工具 JSON 参数；完整结果才进入调度。
- 作用机制：把“收到数据”和“允许副作用”分开，失败请求不会触发半个写入动作。
- 改善性质：可靠性。
- 代价：动作要等待当前模型轮次结束；第一阶段尚未实现 token 流式显示。
- 证据：故障实验覆盖 `length`、结束原因不匹配、重复 ID、完整事件后连接失败均不写文件。
- 性能：未测，不能据此声称响应更快。

## OPT-003：第一阶段使用文件独占创建

- 风险：普通写入模式可能覆盖用户已有文件；单独“先判断不存在再写入”还存在判断与创建之间的竞争窗口。
- 实现：使用 Python `open("xb")`，把“不得存在”和“创建”交给同一次系统调用。
- 作用机制：即使已有同名文件，也会返回结构化错误并保留原内容。
- 改善性质：可靠性，且减少第一阶段需要理解的编辑规则。
- 代价：当前不支持覆盖与编辑；路径检查仍不是操作系统沙箱，也没有声称解决所有文件系统竞争问题。
- 证据：文件已存在与演示重复运行的测试检查原内容不变。
- 性能：未测；不声称比其他写入方式更快。

## OPT-004：外部成功响应也做业务结构检查

- 风险：HTTP 200 只表示传输层成功；缺少候选字段会让初版适配器抛出未归一化的 TypeError。
- 实现：SDK 边界先检查候选存在且唯一，再转换为内部类型；对应字段缺失与空列表都有离线故障实验。
- 作用机制：异常留在模型适配边界，以 `ModelFailure` 交给 Runner 受控结束，避免泄露第三方异常细节或执行不完整动作。
- 改善性质：可靠性；不能据此声称模型任务成功率提升。
- 代价：额外维护边界校验及测试；尚未覆盖任意畸形 JSON。
- 证据：修复前缺字段用例真实失败，修复后结果见进度文档。
- 性能：未测。

## OPT-005：通用启动说明与 IDE 配置隔离

- 原问题：README 启动步骤依赖作者本机路径，新增的 `.idea/` 文件也出现在待提交清单中。
- 实现：改为从克隆后的仓库根目录启动，明确 uv 与 Python 准备步骤，统一使用 `--locked`；忽略 `.idea/` 而不删除本机配置。
- 作用机制：减少其他机器复现项目时需要替换的路径，保持依赖版本一致，并减少提交中的个人 IDE 配置噪声。
- 改善性质：可复现性与可维护性；运行时性能未测，没有速度提升结论。
- 验证：结果记录在进度文档。
