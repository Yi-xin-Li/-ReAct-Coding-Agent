# 第一阶段学习日志

## 目标：亲眼看见 Agent 的循环

本阶段先实现模型调用、工具执行和结果回填。真实 DeepSeek 适配器已经提供，离线演示则用固定脚本模拟模型选择，方便在没有 Key 时观察机制。

### 建议阅读顺序

1. `src/mini_agent/types.py`：先分清 Message、ToolCall、ToolResult 和 ModelTurn。
2. `src/mini_agent/tools.py`：看普通 Python 文件操作如何变成模型可选择的工具。
3. `src/mini_agent/agent.py`：找到循环中的模型调用、工具执行和结果写回。
4. `src/mini_agent/model.py`：看内部消息如何转换为官方接口格式。
5. `src/mini_agent/cli.py`：确认终端只是输入输出层，不负责决定模型下一步做什么。

### 四轮演示的数据流

```text
用户：读需求并创建 hello.py
第 1 轮：assistant 返回 read_file 调用 → 执行读取 → tool 返回需求内容
第 2 轮：assistant 返回 write_file 调用 → 创建文件 → tool 返回写入结果
第 3 轮：assistant 返回 read_file 调用 → 读回源码 → tool 返回源码
第 4 轮：assistant 返回普通文字，没有工具调用 → 循环结束
```

工具定义的 JSON Schema 告诉模型“有哪些行动、参数应该是什么”。调用中的 ID 将行动与结果关联。模型并不因为输出 `write_file` 就能操作磁盘，真正写文件的是宿主执行的 Python 函数。

消息历史每轮增长。下一次模型调用可以看见需求、之前的调用和实际结果，因此能调整行动。这是 ReAct 的行动—观察反馈机制；不需要强迫模型输出一段完整思维链。

### 模型与工程代码分别承担什么

| 能力 | 负责人 |
| --- | --- |
| 选择工具、生成参数和代码、根据错误调整 | 真实运行时由模型负责；离线演示由固定脚本模拟 |
| 解析 JSON、校验参数、检查路径、读写磁盘 | Python 工程代码 |
| 对应调用 ID、追加结果、限制步数、判断协议是否完整 | Agent Runner |
| 展示结果、接收输入 | CLI |
| 判断程序符合任务要求 | 独立测试和人工检查；模型一句“完成”不能证明 |

### 本阶段边界

- `stream()` 是稳定的模型事件接口，当前实际请求 `stream=False`，只产生完整轮次事件。token 增量展示和参数分片组装将在第二阶段实现。
- 文件工具只创建新文件，不覆盖已有内容。局部编辑与并发修改检测留到第二阶段。
- 多轮对话在内存中保留历史；没有实现磁盘保存或断点恢复。
- 输入超过硬上限会停止；自动压缩将在第三阶段实现。
- SDK 隐式重试关闭，本阶段没有自动重试策略或累计人民币费用账本。

### 理解练习

1. 找到 `self._messages.append(...)`，解释新增消息属于哪个角色，以及为什么需要它。
2. 用自己的话解释工具 schema 和工具实现之间的关系。
3. 查看 JSON 事件，找到 `read_file` 的调用 ID 与对应结果。
4. 将需求改为不同文件名后思考：为什么离线演示不会像真实模型那样理解新任务？
5. 阅读“非法参数”和“错误后调整”的测试，解释为什么返回结构化错误比直接让循环崩溃更有用。
6. 解释为何“文件读回成功”“脚本运行成功”“任务验收测试通过”是三种不同证据。

完成标准：能画出四轮数据流，解释调用 ID 和停止条件，运行演示并查看生成文件，定位一个故障实验的预期行为。

### 本轮实际排障带来的知识点

- 发布包名与 Python 导入包名可以不同，但构建配置需要明确源码路径。
- Windows 换行与终端编码是两类问题：读取保留文件换行，终端输出则通过项目环境设置 UTF-8。
- 功能测试通过仍要做静态检查；异步函数中的阻塞子进程被 Ruff 发现后已改成异步调用。
- HTTP 200 不保证业务字段完整；故障注入发现缺 `choices` 会导致 TypeError，修复后在适配器边界受控处理。
- 最终 42 个离线用例通过只证明本轮覆盖的宿主行为，不证明真实 LLM 的任务成功率。

### GitHub 发布前整理

- README 的启动步骤以仓库根目录为起点，移除作者机器上的绝对路径；别人克隆到任意位置仍可照着操作。
- 命令统一使用 `--locked`，复用仓库中的依赖锁文件；解释器和缓存仍由开发脚本放在项目内。
- `.idea/` 是本机 IDE 配置，加入忽略规则即可，不删除用户现有 IDE 文件；`.env.example` 继续保留为配置示例。
