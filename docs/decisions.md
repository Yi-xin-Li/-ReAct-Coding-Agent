# 架构决策

## ADR-001：先做显式循环和两个文件工具

- 决策：不用 Agent 框架；第一阶段只注册 `read_file` 与 `write_file`。
- 原因：先让学习者看清消息、调用、执行与反馈，再增加搜索、编辑和命令执行。
- 后果：暂时无法自动运行测试，必须明确标注当前能力边界。

## ADR-002：内核输出事件，终端消费事件

- 决策：`Agent.run()` 返回异步事件序列，Rich 和终端输入只出现在 CLI。
- 原因：同样的工具开始、结果、错误和结束事件以后可接到 Web 的 SSE 入口。
- 后果：需要定义少量数据类型；当前不提前实现 Web 服务或数据库。

## ADR-003：先关闭 SDK 自动重试

- 决策：SDK 设置 `max_retries=0`。
- 原因：先让请求次数、错误和用量可解释；之后再在一个明确位置加入有限重试并计入账本。
- 后果：第一阶段临时网络错误会结束当前任务；不会自动重放工具副作用。

## ADR-004：Python 版本由项目管理

- 决策：通过 uv 在 `.tools/python` 安装 Python 3.12，使用锁文件和 `.venv`。
- 依据：当前机器的 `py -3.12` 注册路径不能启动；项目需要可复现的运行环境。
- 后果：首次安装需要下载解释器；不修复或替换系统 Python。
